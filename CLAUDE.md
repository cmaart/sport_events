# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static site listing amateur cycling races and triathlons in Austria for the 2026 season, deployed to GitHub Pages at `https://cmaart.github.io/sport_events/`. UI is German with strings externalized; site is client-rendered interactive (filter + Leaflet map) on top of a fully prerendered Astro build.

## Common Commands

```bash
npm install         # install
npm run dev         # dev server → http://localhost:4321/sport_events/
npm run build       # production build → ./dist (24+ pages: index + one per event)
npm run preview     # preview the production build
npm run check       # astro check (type + content schema validation)
```

There is no test suite. Validation is enforced at build time via Zod schemas — adding a malformed event JSON will fail `npm run build` (and CI) with a precise field-level error.

## Deployment

- **Default branch is `master`** — `.github/workflows/deploy.yml` triggers on push to `master` and `workflow_dispatch`. (A `main` branch may also exist as a leftover; the workflow is bound to `master`.)
- Pages must be configured to source = "GitHub Actions" in repo settings (one-time setup).
- The `github-pages` environment needs `master` allowed in "Deployment branches and tags" — by default GitHub may restrict it.

## Architecture

### Data model

Events live as one JSON file per event under `src/content/events/`. The Zod schema in `src/content.config.ts` validates them at build time via Astro Content Collections. Files prefixed with `_` (e.g. `_template.json`) are excluded by the glob loader pattern `**/[^_]*.json`.

The event slug is derived from the filename (without `.json`), not from the `id` field inside the JSON. Detail page routes are generated by `src/pages/events/[slug].astro` via `getStaticPaths()`.

### Critical split: server-only vs browser-safe constants

`src/content.config.ts` imports `astro:content`, which is a **server-only virtual module**. Importing from it (even just types) in any file that ends up in the client bundle breaks the Vite build with a `ServerOnlyModule` error.

To avoid this:
- `src/lib/types.ts` holds the plain TypeScript constants and union types (`SPORTS`, `CATEGORIES`, `REGIONS`, etc.)
- `src/content.config.ts` imports from `lib/types.ts` and wraps them in Zod enums
- **Client islands and `lib/*` must import constants and types from `lib/types.ts`, never from `content.config.ts`**

If you add a new sport/category/region, update `lib/types.ts` — Zod picks it up automatically.

### Interactivity: islands

`src/pages/index.astro` is a static Astro page that serializes the event collection to props and mounts a single Preact island `<EventsExplorer client:load>` (`src/components/islands/EventsExplorer.tsx`). That parent island owns the filter + selection state and renders three children:

- `FilterBar` — sport toggle, category chips (sport-aware), region chips, date range, search, "upcoming only" toggle
- `EventList` — sortable, hover/click selection synced with map
- `EventMap` — lazy-loaded via `lazy()` + `<Suspense>` because Leaflet touches `window` at import time

Filter state is mirrored to URL query params (`?sport=…&kat=…&region=…&from=…&to=…&q=…&past=1`) in `src/lib/url-state.ts` via `history.replaceState`. Initial state is hydrated from `location.search` on mount. Pure filter logic lives in `src/lib/filters.ts`; fuzzy search index is in `src/lib/search.ts` (MiniSearch).

### Map gotchas

- Leaflet's CSS and `leaflet.markercluster` CSS are imported in `EventMap.tsx`.
- Marker icons are rendered as `L.divIcon` HTML to avoid default-icon 404s under the `/sport_events` base path.
- The map fits bounds to currently filtered events; selecting a marker calls `cluster.zoomToShowLayer()` before opening the popup.

### i18n

All UI strings are in `src/i18n/de.json` (flat key-value), accessed via `t(key, params?)` from `src/lib/i18n.ts`. There is no runtime locale switching yet — adding another locale only requires a sibling JSON file plus a small change in `i18n.ts`. Dates are formatted via `formatDate`/`formatDateRange` helpers, which use the same translation table for month names.

### Base path

`astro.config.mjs` sets `site: 'https://cmaart.github.io'` + `base: '/sport_events'`. All internal links must use `import.meta.env.BASE_URL` (in `.astro` files) or the `baseUrl` prop passed into islands. The dev server serves under `/sport_events/`, not `/`.

## Adding an Event

1. Copy `src/content/events/_template.json` to `src/content/events/<kebab-slug>-2026.json`.
2. Fill in fields. Allowed values for `sport`, `categories`, `location.region` are enumerated in `src/lib/types.ts`. Set `dates.confirmed: false` if the 2026 date is not officially announced yet — the UI then renders "Datum noch offen".
3. Get `lat`/`lng` from openstreetmap.org (right-click → "Show address").
4. `npm run build` to validate the schema. CI will also block invalid events.

## Content Style

Event descriptions are German prose, 2–4 sentences, factual: location, route highlights, distances/elevation, registration peculiarities (lottery, sold out). The README is the user-facing contributor doc; this file is the working doc for Claude.

## Source Reliability (for event facts)

When verifying event facts (dates, distances, elevation), prefer primary/official sources and avoid known-unreliable secondary sources.

- **Trusted**: the event's official website, official race-organiser social channels, official federation calendars (DTU, ÖTRV, BDR, ÖRV, UCI, ITU/World Triathlon), ironman.com, challenge-family.com, Wikipedia for cross-checks of historical editions.
- **Treat with caution / cross-check**: aggregator sites (ahotu, finishers, runme, hdsports, triafreunde, racecheck, etc.) — often have stale dates or copy-pasted errors. Use only when the official site does not state the fact.
- **Do NOT use as a source**:
  - `prommer.net` — flagged as unreliable; do not cite for distances/elevation/dates.

If only an unreliable source carries a fact, leave the field out (e.g., omit `elevationGainM`) rather than guessing.
